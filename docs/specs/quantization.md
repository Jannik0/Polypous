# Spec: Quantized Weights and Kernels

**Status:** Draft. Implemented in M3. **Crate:** `polypous-quant` · **Decision:** [ADR-0005](../adr/0005-native-quantized-kernels.md)

Quantized models must stay quantized in memory: a 7B Q4_K_M model should take ~4.5 GB, not ~14 GB.
Polypous therefore runs computations directly on GGUF block formats.

## 1. Scope

| Tier | Formats | Treatment |
|---|---|---|
| **Native (v1)** | `Q8_0`, `Q4_K`, `Q5_K`, `Q6_K` | Kept quantized; dedicated GPU + CPU kernels |
| **Native (later)** | `Q4_0`, `Q5_0`, `Q2_K`, `Q3_K`, `IQ4_XS`, … | Added based on what users download |
| **Fallback** | Every other GGUF type | Dequantized to `f16` when loading, with a warning that includes the extra memory |
| **Float** | `F32`, `F16`, `BF16` | Standard Burn tensors |

`Q4_K_M` / `Q5_K_M` files mix `Q4_K`/`Q5_K` with `Q6_K` (and sometimes `Q8_0`) per tensor, so the v1
set covers the most popular files completely.

## 2. Block layouts (reference)

All formats quantize along the **last (row) dimension**. Row length must be a multiple of the block
size. Layouts are byte-compatible with ggml, and ggml's `block_*` struct definitions are the
authoritative source.

| Format | Elements/block | Bytes/block | Bits/weight | Layout |
|---|---|---|---|---|
| `Q8_0` | 32 | 34 | 8.5 | f16 scale `d`; 32 × i8 |
| `Q4_K` | 256 | 144 | 4.5 | f16 `d`, f16 `dmin`; 12 B packed 6-bit scales/mins for 8 sub-blocks; 128 B 4-bit quants |
| `Q5_K` | 256 | 176 | 5.5 | as Q4_K + 32 B high bits |
| `Q6_K` | 256 | 210 | 6.5625 | 128 B low 4 bits; 64 B high 2 bits; 16 × i8 sub-block scales; f16 `d` |

## 3. Representation

```rust
pub struct QTensor {
    format: QuantFormat,     // Q8_0, Q4_K, ...
    shape: Vec<usize>,       // logical shape, e.g. [out_features, in_features]
    data: QStorage,          // raw block bytes, on a device or memory-mapped
}
```

- Device-resident storage is a raw byte buffer. Whether it uses a Burn tensor type (for example a
  `u8`/`u32` int tensor, or Burn's own quantized tensor type if it can carry GGUF blocks) or a CubeCL
  buffer handle directly is decided by a **spike at the start of M3**, recorded as an ADR.
- CPU-tier and Disk-tier storage may point straight into the memory-mapped file (zero copy).
- `QTensor` is a parameter type only. Activations are always `f32`/`f16`.

## 4. Operations on quantized tensors

| Op | Use | Kernel(s) |
|---|---|---|
| `dequantize` | Fallback, debugging, transforms | GPU + CPU |
| `qmatvec` | `nn.linear` with few rows of activations (token-by-token decoding, batch ≤ 8) | GPU: per-row dot product with in-register dequantization · CPU: SIMD dot product |
| `qmatmul` | `nn.linear` with many rows (prompt prefill, ASR, diffusion) | GPU: dequantize tiles into shared memory as f16, then tiled matmul · CPU: dequantize row panels + f32 GEMM |
| `qget_rows` | `nn.embedding` | Dequantize the selected rows only |

The runtime picks `qmatvec` or `qmatmul` by the row count of activations. Any other op that receives a
quantized param dequantizes it first and logs a debug message.

## 5. Kernel implementation

- **GPU:** written once in **CubeCL**, compiled for CUDA, Vulkan (SPIR-V via wgpu) and Metal.
  Do not write separate CUDA/GLSL/MSL kernels unless CubeCL cannot express something, and record that in an ADR.
- **CPU:** Rust with runtime SIMD dispatch (`AVX2`/`FMA`, `AVX-512` where available, `NEON` on ARM)
  and a scalar fallback that is the CPU reference. Parallelized over output rows with `rayon`.
- **Accumulation** is in f32. CPU kernels may quantize activations to 8 bits for faster integer dot
  products (like ggml's `Q8_K` path) only behind a flag, after the float path is correct.

## 6. Correctness

| Test | Reference | Tolerance |
|---|---|---|
| `dequantize` per format | `gguf-py` (`gguf.quants.dequantize`) on fixture blocks, including edge cases (zero scales, extreme values) | **bit-exact** in f32 |
| `qmatvec` / `qmatmul` | Dequantize → f64 matmul | max relative error ≤ 1e-3 (f32 accumulation), ≤ 1e-2 for f16 paths |
| Scalar CPU vs SIMD CPU vs GPU | Each other | Same as above |
| End-to-end | llama.cpp logits for a fixed prompt | See [testing-strategy.md](../testing-strategy.md) |

Fixture blocks are generated by `tools/reference/` and stored in `fixtures/small/quant/`.

## 7. Later

Quantizing f16 safetensors models when loading (for example to Q8_0/Q4_K) so they fit on small
machines ([project brief Q4](../project-brief.md#10-open-questions)) · KV-cache quantization ·
importance-matrix (`IQ*`) formats.
