# Upstream findings register

Every problem Polypous found in a dependency it doesn't own: Burn, CubeCL and cubek, and GPU
drivers. For each one it records what Polypous does about it and where it stands upstream.
[status.md §4](status.md#4-known-limitations-and-open-items) describes the user-visible limitations in
detail; this register is the numbered list behind them. How findings are handled is in
[development-workflow.md §8.7](development-workflow.md#87-upstream-burn-and-cubecl-findings).

## Rules

- **IDs** are `M<milestone>-<n>`, numbered in the order the findings were made, and never reused or
  renumbered. One sequence per milestone covers both tables below, so an ID is unique. Hand-off
  prompts to the owner's upstream agent refer to these IDs.
- **The lead keeps this file current.** When a worker reports a new finding (under "Decisions" in its
  PR, with a reproduction), the lead adds the row in the same PR or in the next docs PR. When the
  upstream agent reports back, the lead fills in "Upstream". A finding stays in the register after
  it is fixed; its row then says in which version.
- **Re-check after a Burn upgrade** ([ADR-0007](adr/0007-burn-version-pinning.md)): every row with
  "Yes" must be tested again. Switch the workaround off and run the fixtures that showed the problem
  (the negative check of the PR named under "Found in"). If they pass, the workaround can go, in its
  own PR. "Partly" means the workaround is required by the spec anyway, so the re-check is for
  information.
- **Versions:** unless a row says otherwise, Burn 0.22.1, CubeCL 0.11.3 and cubek 0.3.1
  (cubek-matmul, cubek-pool, cubek-random), as pinned by ADR-0007. `flex` is Burn's CPU backend.
  Lavapipe in CI and in cloud sessions is Ubuntu's Mesa 25.2.x. The reference machine runs NVIDIA
  621.14 and Intel 32.0.101.7092 on Windows, and NVIDIA 620.70.06 and Mesa 25.0.7 on Debian.
- **Upstream state:** "Handed off (date)" means the owner gave the finding to the upstream agent on
  that date; "In the … hand-off prompt" means the lead wrote it into a prompt that hasn't been
  confirmed as passed on yet. Upstream links come from the upstream agent's reports; where a row has
  none, they are still to be added.
